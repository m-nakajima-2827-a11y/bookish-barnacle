# デザイン仕様と生成手順

元提案（17枚）で使い、Googleスライドで表示を確認したデザインです。顧客や自社のブランドカラーがあれば、配色だけ差し替えて使えます。

## 1. 基本設定

| 項目 | 値 | 理由 |
|---|---|---|
| サイズ | 16:9 ワイド（13.333 × 7.5 インチ、pptxgenjs の `LAYOUT_WIDE`） | 表や3列カードを14pt以上で収めるため |
| フォント | Noto Sans JP（見出し・本文とも） | Googleスライドで標準利用でき、変換後も崩れにくい |
| 余白 | 左右0.6インチ | |
| タイトル | 上端0.35インチ、高さ1.05インチ、26pt太字、2行まで | 日本語のストーリータイトルが2行に収まるサイズ |
| 本文開始位置 | 上端1.55〜1.6インチ | |
| フッター | 左に資料名、右にページ番号（10pt、グレー） | |
| 脚注 | 上端6.7インチ、10pt、グレー | 出典・仮説の注記 |

## 2. 配色（トークン）

| トークン | 色 | 用途 |
|---|---|---|
| BG | `FAFAFA` | 本文スライドの背景（真っ白は避ける） |
| TX | `1F2933` | 本文の文字 |
| MU | `5B6670` | 補足・フッター・表の見出し |
| AC | `0E7C7B`（ティール） | 基本のアクセント。カード見出し、番号の丸、矢印 |
| ACL | `E3F1F0` | ACの薄い色。強調ボックス、重点行の網掛け |
| HL | `B45309`（オレンジ） | 最も見てほしい1点だけに使う強調色 |
| HLL | `FDF1E4` | HLの薄い色 |
| LN | `DADFE3` | 罫線・カードの枠 |
| DK | `0F2A2E` | 表紙の背景 |

使い方のルール:
- 1枚の中で強調色（HL）は1〜2か所まで。「最初に着手するもの」「承認ポイント」「組織品質KPI」のように、メッセージの核にだけ使います。
- 色は意味を持たせて統一します（AC＝標準、HL＝重点）。
- 帯状の装飾バーや、タイトル下のアクセント線は使いません。

## 3. 部品

| 部品 | 仕様 | 使うスライド |
|---|---|---|
| カード | 角丸四角、白地、LNの枠1pt。見出し17pt太字AC、本文15〜16pt、箇条書きの段落後8pt | 3, 6, 12, 13, 14, 15 |
| 番号の丸 | 直径0.4〜0.6インチ、AC塗り、白の太字数字 | 2, 9, 11, 17 |
| 表 | 罫線は行の間だけ（LN 0.75pt）、見出し行の下にMU 1.5pt。見出し行は太字・塗りなし、1列目は太字。本文14pt、行の高さ0.42〜0.55インチ | 4, 5, 8 |
| 矢印フロー | 1つ目は五角形、2つ目以降はシェブロン。ラベルは12〜16pt太字白、2行以内 | 10, 16 |
| 強調ボックス | ACLまたはHLL塗り、枠なし | 2, 4, 14, 15, 17 |
| 区分ブロック | A〜Dの色を濃→淡（AC、`3F9A98`、`8FA3A6`、`B8C2C4`） | 11 |

## 4. 文字サイズ

| 要素 | サイズ |
|---|---|
| 表紙タイトル | 44pt太字 |
| スライドタイトル | 26pt太字 |
| カード見出し | 16〜18pt太字 |
| 本文・箇条書き | 14〜16pt（14pt未満にしない） |
| 補足 | 13〜14pt |
| 脚注・フッター | 10〜12pt |

収まらない場合は、文字を小さくするのではなく、文言を削るかスライドを分けます。

## 5. 生成手順

### 5-1. pptxを作る
1. `pptx` スキルを読み込み、pptxgenjs のスクリプトを書きます（`pres.layout = "LAYOUT_WIDE"`）。
2. 共通関数として、タイトル・フッター・脚注を置く `base()`、カード、番号の丸、表の関数を用意すると、17枚を同じ見た目で作れます。
3. 日本語を正しくプレビューするため、Noto CJKフォントがなければ入れ、`Noto Sans JP` を `Noto Sans CJK JP` に割り当てます（fontconfig）。
4. 生成後、`validate.py` で検査し、LibreOfficeでPDFにして画像で全ページを確認します。

### 5-2. Googleスライドにする
1. `google-workspace` スキルを読み込みます。
2. Googleドライブの `create_file` で、pptxのMIMEタイプを指定してアップロードします（Googleスライドに自動変換されます）。
3. Googleスライドのコネクタがある場合: PDFで書き出し、`render_export.py` で画像にして全ページを確認します。直す箇所は `update_presentation` で、同じファイルのまま修正します（リンクを変えないため）。
4. コネクタがない場合: 変換後のテキストをドライブで読み、文字が欠けていないことだけ確認し、Googleスライド上の見た目は未確認であるとユーザーに伝えます。

## 6. よくある崩れと対処

| 症状 | 対処 |
|---|---|
| 矢印や狭いボックスのラベルが、単語の途中で改行される | 意味の切れ目に改行を入れる（例:「開発責任者が／引き継ぎ内容を承認」） |
| カードの下半分が空く | 本文の文字を15〜16ptに上げるか、カードの高さを縮める |
| 脚注が本文のカードに重なる | カードの高さを縮め、脚注の上に0.1インチ以上の余白を取る |
| 表が下にはみ出す | 1行の文字数を減らすか、行を分割してスライドを分ける |
| タイトルが3行になる | 修飾語を削り、40字以内にする |
