# クレープ店 収支管理スキル

クレープ店のオーナーが「どの商品・どのチャネルで、いくら儲かっているか」を毎月つかみ、値付け・原価・固定費の打ち手を判断できるようにするスキルです。

成果物は2つです。

1. **収支管理ワークブック**（.xlsx。Googleスプレッドシートにそのまま取り込める）
2. **収支レポート**（入力済みブックを読み取って作る、現状・課題・原因・打ち手・KPIの報告書）

## このスキルの考え方

収支管理は「売上 − 経費」を見るだけでは改善につながりません。次の3つを分けて見られるようにすることが要点です。

| 見る単位 | わかること | 主な打ち手 |
|---|---|---|
| **商品** | 1個あたり原価・原価率・粗利 | 値付け、レシピ（盛り量）調整、メニュー入替 |
| **チャネル**（店舗／キッチンカー／自販機） | どの販売手段が固定費を回収できているか | 営業日・出店先・設置場所の見直し、撤退・強化判断 |
| **月** | 季節変動、損益分岐点との距離 | 繁閑に応じた人員・仕入・販促の調整 |

あわせて **理論原価（レシピ×販売数）と実際原価（仕入±棚卸）の差** を毎月見ます。差が大きいほど、廃棄・盛りすぎ・記録漏れ・仕入価格の上昇が起きている可能性が高く、原価改善の起点になります。

## 前提（ユーザーから共有済みの事実）

- 販売チャネル：実店舗1店、キッチンカー、店舗設置型冷蔵自販機
- 販売単価：650〜800円/個（税込と想定。税抜の場合は商品マスタの価格を税抜換算せず入力し直すよう案内する）
- 出力形式：Excel またはGoogleスプレッドシート

これ以外の数値（原価、家賃、人件費、販売数など）は**ユーザーの実データが入るまで仮置きしない**。サンプルが必要な場合は `--sample` で生成し、「架空データ」と必ず明記する。

## 作業の流れ

### Step 1. 依頼の種類を判定する

| 依頼の例 | やること | 使うもの |
|---|---|---|
| 「収支管理表がほしい」「テンプレートを作って」 | 空のワークブックを生成して渡す | `scripts/build_workbook.py` |
| 「使い方を見たい」「動作を確認したい」 | サンプル入りワークブックを生成 | `build_workbook.py --sample` |
| 「この商品の原価率は？」「800円にしたら？」 | 会話内で計算し、ブックの該当シートの入力方法も示す | `references/cost-calculation-guide.md` |
| 「今月の収支をまとめて」（入力済みブックあり） | ブックを解析し、収支レポートを作る | `scripts/analyze_workbook.py` ＋ `references/report-template.md` |
| 「シートを追加・変更したい」 | `build_workbook.py` を修正して再生成 | `references/workbook-spec.md` |

### Step 2. 必要情報を確認する（不足時は最大3点まで）

テンプレート生成だけなら確認なしで進めてよい。次の3点だけは、わかれば反映する。

1. **事業年度の開始月**（個人事業なら1月、法人なら決算月の翌月）→ `--fy-start`
2. **店舗名**（表示用）→ `--shop`
3. **販売価格が税込か税抜か**、イートインの有無（税率10%／8%の判定に使う）

原価・経費の数値は聞き出さず、ブックの黄色セルに入力してもらう。

### Step 3. ワークブックを生成する

```bash
# 空のテンプレート
python scripts/build_workbook.py --out <出力先>/crepe_accounting.xlsx --shop "店舗名" --fy-start 2027-04-01

# 動作確認用（架空のサンプルデータ入り）
python scripts/build_workbook.py --out <出力先>/crepe_accounting_sample.xlsx --sample --fy-start 2027-04-01
```

- 依存は `openpyxl` のみ。生成済みのものが `assets/` にもある（template＝空、sample＝架空データ）。
- 生成後、LibreOffice があれば再計算してエラー（`#REF!` `#VALUE!` など）がないことを確認してから渡す（確認手順は `references/workbook-spec.md` の「検証」）。
- Googleスプレッドシートで使う場合：Googleドライブにアップロード →「アプリで開く」→「Googleスプレッドシート」。使用関数（SUMIFS / VLOOKUP / IFERROR / EDATE / EOMONTH / ROUND / N）はすべて互換。

### Step 4. 使い方を説明する

渡すときは、次の順で「最初の1回」と「毎日・毎月」を分けて案内する。シート構成と各列の意味は `references/workbook-spec.md` にある。

| タイミング | シート | 入力内容 |
|---|---|---|
| 最初に1回 | 設定 | 店舗名、事業年度開始日、表示月、配賦方法、目標営業利益、目標原価率 |
| 最初に1回 | 材料マスタ → レシピ → 商品マスタ | 材料の購入価格・量・歩留まり → 商品ごとの使用量 → 販売価格 |
| 最初に1回 | 設備 | 焼き機・冷蔵庫・キッチンカー車両・自販機などの取得価額と耐用年数 |
| 毎日 | 売上入力 | 日付・チャネル・商品・販売数・廃棄数（POSの商品別日報を貼り付けても可） |
| 都度 | 経費入力 | 日付・費目・チャネル・税込金額 |
| 月末 | 棚卸 | チャネル別の材料・包材の残高（税抜） |
| 月初 | 月次損益・年間推移 | 前月の結果を確認（Step 5 のレポート作成へ） |

### Step 5. 収支レポートを作る（入力済みブックがある場合）

```bash
python scripts/analyze_workbook.py <入力済み>.xlsx --month 2027-05
```

1. スクリプトの出力（チャネル別損益・KPI・自動判定・年間推移）を事実として使う。
2. `references/report-template.md` の構成で、**現状 → 課題 → 原因 → 打ち手 → 効果 → KPI → 次のアクション** にまとめる。
3. 原因の切り分けは `references/cost-calculation-guide.md` の「診断の型」を使う。
4. 打ち手の効果は、シミュレーションシートの式と同じ計算で試算し、**「試算」「想定」と明記**する。前提（販売数・単価・原価）も併記する。

## 品質基準

- **事実と仮説を分ける**：ブックから出た数値は事実、改善効果は「試算」、原因は「仮説」と書き分ける。
- **根拠のない数値を作らない**：業界平均の原価率などを断定的に使わない。使う場合は「一般的な目安」と明記し、自店実績との比較に留める。
- **税務判断はしない**：消費税（軽減税率の適用範囲・インボイス）、減価償却（耐用年数・少額特例）、確定申告の判断は税理士確認を促す。ブックは管理会計用の概算であることを伝える。
- **課題・施策・効果の一貫性**：レポートで挙げた課題には、必ず対応する打ち手とKPIを置く。
- **チャネル撤退の判断は慎重に**：共通費配賦後の営業利益が赤字でも、チャネル貢献利益が黒字なら「撤退すると共通費を他チャネルで負担することになり全社利益は減る」点を必ず説明する。

## ファイル構成

| パス | 内容 |
|---|---|
| `scripts/build_workbook.py` | ワークブック生成（`--sample` で架空データ入り） |
| `scripts/analyze_workbook.py` | 入力済みブックの再計算・解析 → Markdownレポートの素材 |
| `references/workbook-spec.md` | 全シートの列定義・計算式・集計ロジック・検証方法・カスタマイズ方法 |
| `references/cost-calculation-guide.md` | 原価計算の考え方、チャネル別の費目の振り分け、KPI定義、診断の型 |
| `references/report-template.md` | 月次収支レポート（改善提案つき）の構成テンプレート |
| `assets/crepe_accounting_template.xlsx` | 空のテンプレート（事業年度 2027/04 開始で生成。設定シートで変更可） |
| `assets/crepe_accounting_sample.xlsx` | 架空データ入りサンプル（2027年4〜5月） |
