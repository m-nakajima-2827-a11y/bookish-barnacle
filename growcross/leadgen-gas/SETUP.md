# 導入手順書（AI×GAS 営業リード獲得の自動化）

所要時間の目安：初回 60〜90分。設計の考え方は [`README.md`](README.md) を参照してください。

## 0. 事前に用意するもの

| 項目 | 入手先 | 保存場所 |
|---|---|---|
| Claude API キー | Anthropic Console（console.anthropic.com）> API Keys | スクリプトプロパティ `ANTHROPIC_API_KEY` |
| Google Places API キー | Google Cloud Console で「Places API (New)」を有効化 → 認証情報 > APIキー（API制限で Places API のみに限定） | スクリプトプロパティ `PLACES_API_KEY` |
| Google Chat の Webhook URL（任意） | 通知したいスペース > アプリと統合 > Webhook | スクリプトプロパティ `CHAT_WEBHOOK_URL` |
| 送信ドメインの認証 | Google Workspace 管理コンソールで DKIM を有効化、DNSに SPF・DMARC を設定 | — |

> APIキーはシートやコードに書かず、必ずスクリプトプロパティに保存してください。

## 1. スプレッドシートとコードの準備

**方法A：画面から貼り付ける（おすすめ）**
1. Googleスプレッドシートを新規作成（名前例：`営業リード自動化`）。
2. 「拡張機能 > Apps Script」を開く。
3. `gas/` フォルダの各ファイルを同じ名前で作成し、内容を貼り付ける（`.gs` はスクリプト、`FormSidebar.html` は「HTML」で作成）。
4. 「プロジェクトの設定」で「appsscript.json マニフェスト ファイルをエディタで表示する」をON → `appsscript.json` を貼り付ける。
5. 左メニュー「サービス」に **Gmail API** が追加されていることを確認（マニフェストで有効化されます）。

**方法B：clasp を使う**
```bash
npm install -g @google/clasp
clasp login
cd growcross/leadgen-gas/gas
cp .clasp.json.example .clasp.json   # scriptId を書き換える
clasp push
```

## 2. 初期設定

1. スプレッドシートを再読み込みすると、メニューに「営業自動化」が表示されます。
2. 「営業自動化 > ① 初期設定」を実行し、権限を許可します（Gmail・スプレッドシート・外部URL・カレンダー）。
3. 「プロジェクトの設定 > スクリプト プロパティ」に `ANTHROPIC_API_KEY`・`PLACES_API_KEY`（任意で `CHAT_WEBHOOK_URL`）を追加します。`SPREADSHEET_ID` と `UNSUB_SECRET` は自動で登録されています。
4. 「設定」シートを入力します（最低限）：
   - `送信元メール`・`テスト送信先`・`事業者名`・`事業者住所`
   - `自社サービス概要`・`ターゲット条件`（確認済みの事実だけを書く）
   - `フォーム入力_メール`・`フォーム入力_電話`

## 3. 配信停止ページの公開

1. Apps Script で「デプロイ > 新しいデプロイ > 種類：ウェブアプリ」。
2. 実行するユーザー：**自分**、アクセスできるユーザー：**全員**。
3. 発行された URL（`https://script.google.com/macros/s/…/exec`）を「設定」シートの `WebアプリURL` に貼り付けます。
4. コードを更新したときは「デプロイを管理 > 編集 > 新バージョン」で同じURLのまま更新します。

## 4. 除外リストの登録（送信前に必須）

「配信停止・除外」シートに、既存顧客・商談中・取引先・競合のドメイン（例：`example.co.jp`）またはメールアドレスを登録します。

## 5. テスト運用

1. 「検索条件」シートで1行だけ「実行」にチェック（最大件数は10程度）。
2. 「② リスト作成」→「③ 企業調査＋AI判定」を手動で実行し、「リスト」シートの AI適合度・課題仮説・パーソナライズ文を確認します。
3. 違和感があれば「設定」の `ターゲット条件`・`自社サービス概要`、または `Ai.gs` の判定基準を調整します。
4. 送信待ちの数社の「承認」にチェック →「④ メール送信」を実行（平日9〜18時のみ動作）。テストモード中は `テスト送信先` にだけ届きます。
5. 届いたメールで、差し込み・署名・法定表示・配信停止リンク（確認画面 → 停止）を確認します。
6. 「⑤ フォーム営業の文面を作成」→「⑥ フォーム営業を開始」でサイドバーの動作を確認します。

## 6. 本番開始

1. 「設定」の `テストモード` を FALSE、`1日の送信上限` を 10 にします。
2. 「営業自動化 > 自動実行トリガーを登録」を実行します。

| 処理 | 実行タイミング |
|---|---|
| リスト作成 | 毎日 6時台 |
| 企業調査＋AI判定 | 1時間ごと（1回10社） |
| フォーム文面作成 | 毎日 7時台 |
| メール送信 | 30分ごと（平日9〜18時、祝日を除く） |
| 返信・停止・バウンス確認 | 30分ごと |
| 日次レポート | 毎日 18時台 |

3. 1週間後、停止率1%未満・バウンス率2%未満であれば `1日の送信上限` を 30 に上げます。

## 7. 日々の運用（1日15〜45分）

| タイミング | 作業 |
|---|---|
| 朝 | 「リスト」シートを「ステータス＝送信待ち」で絞り込み、内容を確認して「承認」にチェック |
| 日中 | サイドバーでフォーム営業（10件程度） |
| 通知時 | 返信に対応し、商談が決まったらステータスを「商談化」に変更 |
| 18時 | 日次レポートを確認 |
| 週1回 | 「手動確認」の企業へ電話、テンプレートの見直し |

## 8. よくあるエラー

| 症状 | 原因と対処 |
|---|---|
| 「スクリプトプロパティ…が未設定」 | 手順2-3のキーを登録 |
| Places API 403 | APIキーの制限・課金アカウント・Places API (New) の有効化を確認 |
| Claude API 401 | `ANTHROPIC_API_KEY` を確認。429/5xx は自動で再試行します |
| メールが送られない | テストモード・承認・営業時間・1日の上限・適合度・`WebアプリURL` を確認 |
| 送信元エラー | `送信元メール` が Gmail 本人のアドレスか、登録済みのエイリアスか確認 |
| 実行時間の超過 | 1回あたり約4.5分で自動的に止まり、次回の実行で続きから処理します |

## 9. 割り当て（クォータ）の目安

- Gmail の送信数・UrlFetch の呼び出し回数・トリガーの実行時間には、Google Workspace のプランごとの上限があります。最新の値は Google の「Apps Script の割り当て」ページで確認してください。本設計の初期値（30通/日、調査240社/日）は、上限より十分小さい値に設定しています。
