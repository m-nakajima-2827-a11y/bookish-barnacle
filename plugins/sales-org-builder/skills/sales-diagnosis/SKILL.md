# 営業診断（受注・失注分析）

新しい営業ルールを作る前に、過去の案件から事実を集めて「どの顧客に、どの課題を入口として、どのサービスを提案すると受注しやすいか」と「どこで品質がばらついているか」を明らかにする。この診断の結果が、標準営業プロセス・テンプレート・KPIの設計根拠になる。診断を省くと、標準が「誰かの成功体験」になり、現場に定着しない。

## 入力として受け付けるもの

| 入力 | 扱い方 |
|---|---|
| CRM・SFAの案件エクスポート（CSV、スプレッドシート） | 最優先のデータ。列の意味をユーザーに確認してから分析する |
| 受注・失注案件のリストや商談メモ | 構造化されていなければ、`references/data-schema.md` の項目に沿って表に起こす |
| 関係者ヒアリングの記録 | 定性情報として扱い、データと照合する |
| 何もない | ヒアリング設計と分析用シートの雛形だけを作り、データ収集を依頼する |

## 手順

### 1. 分析対象を決める
- 期間: 原則として過去6〜12か月。案件数が少ない企業は全件。
- 対象: 受注10〜20件、失注10〜20件、継続・追加受注につながった案件、赤字・納期遅延・認識違いが起きた案件、長期間動いていない案件。
- 件数が少ないときは、結論を「傾向」ではなく「仮説」として書く。目安として、1区分あたり5件未満の集計結果から断定しない。

### 2. データを整える
`references/data-schema.md` の標準項目に合わせて、Googleスプレッドシートに「案件データ」シートを作る。
- 失注理由・受注理由は自由記述のままにせず、`references/data-schema.md` の分類コードに振り分け、元の記述も残す。
- 欠損している項目は空欄のままにし、推測で埋めない。欠損率は「データ品質」シートに記録する（入力ルールの改善材料になる）。

### 3. 分析する
`references/analysis-playbook.md` の分析観点に沿って集計する。最低限、次の5つを出す。
1. 受注率（全体、業界別、サービス別、リード経路別）
2. ステージ別の移行率と平均滞留日数（どこで止まるか）
3. 受注理由・失注理由の分類別件数
4. 担当者別のステージ移行率の差（個人評価ではなく、プロセスのばらつきを見る目的であることを明記する）
5. 引き継ぎ後のトラブル（見積差し戻し、手戻り、赤字、納期遅延）の原因

集計はスプレッドシートの数式（COUNTIFS、AVERAGEIFS、ピボットテーブル）で作り、元データから再計算できるようにする。手計算した値を貼り付けない。

### 4. 関係者ヒアリングを設計・整理する
データだけでは分からない「なぜ」を補うため、営業担当者・営業責任者・引き継ぎ先の責任者（PM、開発責任者、制作進行など）にヒアリングする。質問項目は `references/interview-guide.md` を使う。記録は「誰が言ったか」ではなく「何が起きているか」で整理し、データと一致する点・食い違う点を分けて書く。

### 5. 課題一覧と優先順位を作る
課題を、提案書の4領域（提案のばらつき／ヒアリングのばらつき／引き継ぎ先との連携／案件管理）に分類する。各課題に、根拠（データの数値、ヒアリングの発言要旨）、影響（売上・粗利・工数・顧客満足のどれに効くか）、改善の難易度を書く。最後に、影響が大きく着手しやすいものから上位3つを選ぶ。

## 成果物

| 成果物 | 形式 | 中身 |
|---|---|---|
| 営業診断シート | Googleスプレッドシート | 案件データ／分類コード／集計／データ品質の4シート |
| 営業診断レポート | Googleドキュメント | 要約、分析結果、ヒアリング結果、課題一覧、優先課題3つ、次のステップ |
| 現行営業プロセス図 | ドキュメント内の表、またはスライド | 実際に行われている段階と、段階ごとの問題点 |

レポートの構成は `references/analysis-playbook.md` の「レポートの型」に従う。

## 書き方のルール

- データから言えること（事実）と、そこからの解釈（仮説）を分けて書く。
- 数値には母数を添える（例:「受注率32%（受注8件／商談25件）」）。
- 担当者個人の成績を晒す書き方をしない。個人差は「プロセスが標準化されていない証拠」として扱う。
- 改善効果を数値で書く場合は「想定」「目安」とし、前提を書く。

## Googleファイルの作り方

作成前に `google-workspace` スキルを読み込む。新規ファイルはGoogleドライブで作り、中身はGoogleスプレッドシート・Googleドキュメントのコネクタで書き込む。変更は同じファイルに加え、リンクを変えない。作ったファイルは名前にリンクをつけて報告する。

## 次のスキル

診断結果は `sales-process-design`（標準プロセス設計）の入力になる。優先課題3つと現行プロセス図を引き継ぐ。
