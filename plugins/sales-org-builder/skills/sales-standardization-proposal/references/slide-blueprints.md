# スライド設計図（17枚の標準構成）

各スライドについて、目的・タイトルの型・要素・可変部分・元提案（SHIFT ASIA向け）での記載例をまとめています。`{{ }}` は顧客ごとに書き換える部分です。

記載例はそのまま流用せず、顧客の業種・商材・引き継ぎ先に合わせて書き換えてください。とくにサービス名・拠点名・グループ会社名は、前の顧客のものが残りやすい部分です。

## 1. 表紙

- **目的**: 何の提案かを一目で伝える
- **要素**: タイトル（2行）、サブタイトル（提案の一文要約）、「ご提案資料」などの区分、必要に応じて日付・提出先・提案者
- **タイトルの型**: `{{顧客名}}\n営業体制の改善提案`
- **サブタイトルの型**: `{{分析の起点}}から「標準営業プロセス」を定義し、\n担当者に依存しない{{守りたい品質}}を実現する`
- **元提案の例**: 「成功・失注案件の分析から『標準営業プロセス』を定義し、担当者に依存しない提案品質と開発引き継ぎを実現する」
- **デザイン**: 濃色背景（design-system.md の DK）、白文字

## 2. 結論

- **目的**: 提案全体の結論と進め方を、最初の1枚で伝える
- **タイトル例**: 「結論：最初に取り組むべきは、資料統一や研修ではなく『標準営業プロセス』の定義です」
- **要素**
  - 左（約60%）: 「進める順番」として5ステップ。番号つきの丸と、太字の行動名＋補足1行。最初に着手する1〜2を強調色にする
  - 右（約40%）: 「目指す『営業の均一化』」のボックス
    - × 全員が同じ話し方をすること
    - ○ 担当者が違っても、必要な情報が漏れず、一定品質の提案と引き継ぎができる状態
    - 補足:「資料の統一や研修は、標準プロセスを定義した後に、その中身として整備します」
- **可変部分**: 「引き継ぎ」を顧客の実態に合わせて言い換える（例: 制作進行への引き継ぎ、導入チームへの引き継ぎ）

## 3. 想定される現在の課題

- **目的**: 顧客が「うちのことだ」と感じる課題を4領域で示す
- **タイトルの型**: 「{{課題が起きる構造的な理由}}ため、提案・ヒアリング・連携・案件管理が属人化しやすいと考えられます」
- **要素**: 2×2のカード。各カードに見出し1行と症状4つ
  1. 提案内容が担当者によって異なる
  2. ヒアリング内容にばらつきがある
  3. 営業と{{引き継ぎ先}}の連携に負荷がかかる
  4. 案件管理が担当者の感覚に依存する
- **脚注（必須）**: 課題の根拠と「仮説である」旨。例:「※求人情報に記載された営業の担当範囲（…）からの仮説です。営業診断で検証します。出典：{{媒体名}}（{{顧客名}} 求人情報）」
- **注意**: ヒアリングで聞いた課題がある場合は、それを事実として優先し、残りを仮説で補います。どちらかが分かる書き方にします。

## 4. 営業診断

- **目的**: 新ルールを作る前に、事実を集める工程を示す
- **タイトル例**: 「新ルールを作る前に、過去6〜12か月の案件を分析する『営業診断』から始めます」
- **要素**
  - 左: 分析対象カード（受注案件10〜20件、失注案件10〜20件、継続・追加受注につながった案件、赤字・納期遅延・認識違いが発生した案件、提案から長期間動いていない案件）
  - 左下: 「分析で明らかにすること」:「どの顧客に、どの課題を入口として、どのサービスを提案すると受注しやすいか」
  - 右: 確認項目の表（確認項目｜確認内容、9行）
- **確認項目の標準**: 顧客属性／相談内容／顧客課題／案件規模／受注理由／失注理由／営業活動／{{引き継ぎ先}}連携／継続性
- **可変部分**: 「相談内容」「受注理由」の選択肢を顧客の商材に合わせる。件数は案件数が少ない企業なら「直近の全件」に変える

## 5. 標準営業プロセス

- **目的**: 各段階の名称だけでなく「次へ進む条件」を定義することを示す
- **タイトルの型**: 「{{段階数}}段階の営業プロセスごとに『次へ進む条件』を定義し、{{重点段階}}を重点管理します」
- **要素**: 表（段階｜必須行動｜次へ進む条件）。重点段階の行を薄いアクセント色で塗り、脚注で理由を書く
- **標準の9段階**

| 段階 | 必須行動 | 次へ進む条件 |
|---|---|---|
| ① ターゲット選定 | 業界・企業・想定課題を確認 | 自社の強みと課題が合う |
| ② 初回接点 | 課題仮説を提示して面談化 | 課題確認の面談を設定 |
| ③ 課題ヒアリング | 目的、現状、予算、納期、決裁者を確認 | 解決すべき課題が明確 |
| ④ 案件評価 | 規模、確度、実現性、収益性を確認 | 提案・見積対象として承認 |
| ⑤ 社内設計 | 営業・{{社内関係者}}で方針を検討 | 提案範囲と前提条件が合意 |
| ⑥ 提案・見積 | 体制、工程、価格、効果を提示 | 顧客が比較・検討段階へ移行 |
| ⑦ クロージング | 懸念、競合、決裁手順を確認 | 契約条件が合意 |
| ⑧ 引き継ぎ | 要件、経緯、約束事項を共有 | {{引き継ぎ先の責任者}}が受入確認 |
| ⑨ 継続提案 | 定例会、利用状況、次の課題を確認 | 追加案件を案件化 |

- **重点段階の既定**: ③課題ヒアリング、⑤社内設計、⑧引き継ぎ。インバウンド中心の企業では②を、ストック型商材では⑨を重点に加えることがあります。

## 6. ヒアリングの標準化

- **目的**: 全員が最低限確認する項目を3領域で示す
- **タイトル例**: 「共通ヒアリングシートで、{{領域A}}・{{領域B}}・{{領域C}}の3領域を全員が必ず確認します」
- **要素**: 3列のカード、各6〜7項目
- **標準の3領域**: ビジネス面／{{商材の技術・実務}}面／{{品質・成果}}面
  - ビジネス面（全業種共通）: 相談の背景、経営・事業課題、損失や業務負担、期待効果、利用部門・人数、決裁者・関係部署、予算と希望時期
  - 2列目と3列目は業種で変わります（customization-guide.md を参照）

## 7. ヒアリング後の1ページサマリー

- **目的**: 経験の差を記入項目で吸収し、引き継ぎ先が判断できる形にする
- **タイトル例**: 「商談後は1ページの案件サマリーに整理し、経験に関係なく{{引き継ぎ先}}が判断できる状態にします」
- **要素**: 左に「ねらい」（2文）、右に3×3の記入フォームの見本
- **9項目**: 顧客の目的／現状と課題／課題の原因／優先順位／提案するサービス／想定効果／懸念事項／次回行動／社内で確認が必要な事項（最後を強調色）

## 8. 提案パターンの標準化

- **目的**: サービス単位ではなく顧客課題別に、入口提案と拡張提案をパターン化する
- **タイトル例**: 「サービス単位ではなく顧客課題別に『入口提案』と『拡張提案』をパターン化します」
- **要素**: 表（顧客の課題｜入口となる提案｜拡張提案）6〜8行
- **脚注**: サービス一覧の出典（顧客の公式サイトなど）
- **作り方**: 顧客の公開サービス一覧を読み、①顧客の買い手が抱える課題を書き出す、②小さく始められるサービスを入口に置く、③継続・拡大につながるサービスを拡張に置く。サービスにない提案は書かない
- **元提案の例（オフショア開発）**: 国内エンジニア不足 → ラボ型・受託開発 → QA・保守・追加開発／不具合が多い → 第三者検証・品質診断 → テスト自動化・品質PMO

## 9. 提案書の基本構成

- **目的**: 提案書の型を12項目に揃え、課題から効果までの一貫性を担保する
- **要素**: 3グループ×番号カード
  - 課題を理解する: 1 顧客の事業目的／2 現状と課題／3 課題の原因
  - 解決策を示す: 4 解決方針／5 提案範囲／6 体制・役割分担／7 工程・スケジュール／8 {{差別化要素}}
  - 判断材料を揃える: 9 費用・前提条件／10 期待効果／11 リスクと対応策／12 次のステップ
- **可変部分**: 8番目は、顧客が価格以外で勝ちたい軸にします（品質管理方法、運用体制、セキュリティ、成果保証の考え方など）。その項目だけ強調色にし、「必須項目にすることで、価格だけでなく{{強み}}を毎回伝えます」と下に1行添えます。

## 10. 見積・引き継ぎの標準化

- **目的**: 見積依頼と引き継ぎの必須項目、承認フローを示す
- **タイトルの型**: 「見積依頼と{{引き継ぎ先}}引き継ぎの必須項目を定め、{{責任者}}の承認後に着手します」
- **要素**
  - 左: 見積依頼時の必須項目（2列、約13項目）: 顧客の目的、対象業務・ユーザー、必須機能と希望機能、対象外の範囲、納期、予算、構成、外部連携、品質・セキュリティ条件、顧客側の役割、成果物、検収条件、未確定事項
  - 右: 引き継ぎ時の確認項目（約9項目）: 顧客に説明した内容、契約範囲と対象外、見積前提、顧客の優先順位、意思決定者・実務担当者、顧客の懸念、追加提案の可能性、コミュニケーション方法、営業が継続して担当する範囲
  - 下: 4段の矢印フロー「営業が記入 → キックオフ前レビュー（関係者） → 責任者が承認（強調色） → 着手」
- **注意**: 矢印内のラベルは2行以内にし、単語の途中で改行されないよう、意味の切れ目で改行を入れます。

## 11. 案件評価基準

- **目的**: 「見込み度」の判断を担当者の感覚から共通基準に変える
- **タイトル例**: 「8項目×0〜2点の案件スコアで、担当者の感覚による『見込み度』をなくします」
- **要素**: 左に評価8項目（番号つき）、右にA〜D区分（濃→淡の色）と対応方針
- **標準8項目**: 課題が明確か／予算が確認できているか／導入時期が決まっているか／決裁者と接点があるか／自社の強みが合っているか／競合に対する優位性があるか／実現可能か／顧客側の推進担当者がいるか
- **区分**: A 13〜16点（重点案件・責任者も支援）、B 9〜12点（不足情報を確認し提案へ）、C 5〜8点（継続フォロー）、D 0〜4点（定期接点のみ）
- **脚注**: 「案件確度を売上予測へ反映する場合は、ステージごとの受注確率も統一します」
- **注意**: 点数の区切りは例です。営業診断の結果で調整すると書き添えても構いません。

## 12. KPI設計

- **目的**: 売上（結果指標）だけでなく、先行指標と提案・引き継ぎ品質を測る
- **タイトル例**: 「KPIは売上だけでなく、提案品質と引き継ぎ品質まで測れるよう3階層で設計します」
- **要素**: 3列カード（3列目を強調色で塗る）
  - 新規営業KPI: ターゲット企業数、有効接点数、初回面談数、課題確認済み案件数、提案数、受注数・受注率、平均受注単価、商談から受注までの日数、失注理由
  - 既存営業KPI: 定例会実施率、顧客満足度、追加提案数、アップセル・クロスセル受注額、契約継続率、{{横展開}}件数
  - 組織品質KPI: ヒアリング項目の充足率、提案書レビュー実施率、見積差し戻し率、引き継ぎ不備件数、見積工数と実績工数の差、認識違いによる手戻り件数、事例の登録数
- **注意**: 目標値は書きません。書く場合は「目安」とし、営業診断の結果で設定すると明記します。

## 13. 案件レビューの運用

- **目的**: 週次は意思決定の場、月次は傾向分析の場に分ける
- **要素**: 2列カード
  - 週次（1案件3〜5分）: 顧客の課題、ステージ、受注予定額・粗利益、受注予定時期、決裁者、競合、現在の障害、次回行動・期限、上司や{{引き継ぎ先}}に支援してほしいこと
  - 月次: 業界別受注率、提案サービス別受注率、失注理由、担当者ごとのステージ移行率、チャネル別商談化率、既存顧客からの追加受注率、差し戻し・手戻りの原因

## 14. 営業ナレッジの体系化

- **目的**: 成功・失敗事例を、再利用できる形で蓄積する
- **要素**: 左に「ナレッジとして残すもの」（約10項目）、右に「成功事例の登録フォーマット」（11項目のカード、最後の「他案件で再利用できるポイント」を強調）
- **登録フォーマット**: 顧客属性、相談前の状況、顧客課題、営業が立てた仮説、ヒアリングで判明したこと、提案内容、競合との差、受注理由、売上・粗利益、追加提案の可能性、他案件で再利用できるポイント

## 15. AI活用

- **目的**: AIを営業の各段階に組み込む案と、「AIから始めない」理由を示す
- **タイトル例**: 「AIは営業の各段階に組み込みますが、導入はプロセスと入力項目を統一した後に行います」
- **要素**: 4列カード＋下部の注意ボックス
  - 商談前: 企業情報から課題仮説を作成、類似する過去案件・提案書を検索
  - 商談後: 議事録から課題・決裁者・予算・次回行動を抽出、ヒアリング漏れを自動チェック
  - 提案・連携: 提案書の初稿作成、営業メールの作成、顧客の要望を{{引き継ぎ先}}向けの要件形式に整理
  - 分析・育成: 失注理由の分類・傾向分析、商談ロールプレイ、成功パターンを新人教育に活用
  - 注意: 「元となるデータがばらばらなままでは、AIを導入しても営業品質は均一化できません」
- **可変部分**: 顧客がAI関連の事業をしている場合は「自社営業でAIを実践すること自体が顧客への説得力になる」と添えます。そうでない場合は省きます。

## 16. 90日実行計画

- **目的**: 3段階の進め方と、各段階の成果物を示す
- **タイトル例**: 「90日間で『現状把握 → 標準化 → 定着・改善』の3段階を進めます」
- **要素**: 3列（上に矢印見出し、中央に実施内容、下に成果物ボックス）
  - 1〜30日 現状把握: 営業・関係部門へのヒアリング、受注・失注分析、現行プロセスの可視化、問題点の特定、CRMの入力状況の確認、優先課題を3つに絞る → 現行プロセス図／受注・失注分析／課題一覧／改善優先順位
  - 31〜60日 標準化: ステージと完了条件の定義、ヒアリングシート統一、案件スコア設定、テンプレート作成、週次レビュー開始、2〜3案件で試験運用 → 標準営業プロセス／共通ヒアリングシート／案件評価表／各種テンプレート／レビューシート
  - 61〜90日 定着・改善: 試験運用の検証、テンプレート修正、事例登録、ロールプレイ、KPIダッシュボード運用、AIの試験導入 → 営業マニュアル／KPIダッシュボード／事例データベース／教育計画／次の90日の改善計画
- **可変部分**: 期間は顧客の規模で変えます（小規模なら60日、大規模なら6か月）。担当者を書く場合は、顧客と合意した名前だけにします。

## 17. 次のアクション

- **目的**: 合意してほしいことと、次に必要な情報を明確にする
- **タイトル例**: 「次のアクション：方向性の合意後、営業診断に向けた準備から着手します」
- **要素**: 左に3ステップ（方向性の合意 → 推進体制の決定 → 営業診断の準備）、右に「事前にご確認したい事項」（3〜5項目）
- **確認事項の例**: CRMの利用状況と案件データの取得可否、現在の営業ステージ定義・見積フローの有無、営業担当者数と分担、引き継ぎ先の窓口
- **脚注**: 「※上記は提案上の進め方の案です。日程・担当はご相談のうえ確定します。」
