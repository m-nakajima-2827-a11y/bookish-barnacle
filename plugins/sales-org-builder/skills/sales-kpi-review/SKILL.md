# KPIと案件レビューの設計

売上は結果が出るまで時間がかかり、改善の手がかりにならない。そこで、行動量（先行指標）と、提案・引き継ぎの品質（組織品質指標）を合わせて測る。週次レビューは報告会ではなく、案件ごとに次の手を決める場にする。月次レビューでは、個別案件ではなく傾向を見る。

## 手順

### 1. KPIを選ぶ
`references/kpi-catalog.md` の3階層から、各階層3〜6個を選ぶ。選ぶ基準:
- 営業診断の優先課題に直接つながる指標を必ず入れる
- データが取れない指標は、取れるようになるまで「準備中」として定義だけ置く
- 営業5名以下の組織では、合計10個以内に絞る

### 2. KPIを定義する
指標ごとに、定義・計算式・データ元・更新頻度・担当・目標値の6項目を決める。目標値は、過去実績がある場合はそれを基準に設定し、ない場合は空欄にして「3か月の実績を見て設定」と書く。根拠のない目標値を置かない。

### 3. 週次レビューを設計する
`references/review-formats.md` の週次フォーマットを使う。
- 対象: 案件スコアA・B、または今月・来月に受注予定の案件
- 1案件3〜5分で、9項目を確認する
- 会議の最後に「支援が必要な案件」と「担当・期限」を決める
- レビューで、次へ進む条件を満たしていない案件は段階を戻す

### 4. 月次レビューを設計する
業界別・サービス別の受注率、失注理由、ステージ移行率、チャネル別商談化率、追加受注率、差し戻し・手戻りの原因を見て、テンプレートや提案パターンの改善点を決める。

### 5. ダッシュボードを作る
Googleスプレッドシートに、元データ（CRMのエクスポートまたは案件管理シート）から数式で集計するダッシュボードを作る。構成は `references/review-formats.md` の「ダッシュボードの構成」に従う。

## 成果物

| 成果物 | 形式 | 中身 |
|---|---|---|
| KPI定義書 | Googleスプレッドシート | 階層｜指標｜定義｜計算式｜データ元｜頻度｜担当｜目標値 |
| 週次案件レビューシート | Googleスプレッドシート | 案件ごとの9項目、決定事項、支援依頼 |
| 月次傾向レビューシート | Googleスプレッドシート | 7つの観点の集計と、改善アクション |
| KPIダッシュボード | Googleスプレッドシート | 3階層のKPIの推移、ファネル、失注理由 |
| 会議運営ルール | Googleドキュメント | 目的、参加者、時間配分、事前準備、決定事項の記録方法 |

## 書き方のルール

- 指標名は誰が読んでも同じ意味になるよう、定義と計算式を必ず書く（例:「受注率 = 受注件数 ÷（受注件数 ＋ 失注件数）。継続中は含めない」）。
- 個人ランキングを主目的にしない。担当者別の数値は、支援が必要な工程を見つける目的で使うと明記する。
- グラフを入れる場合は、推移は折れ線、ファネルは降順の横棒、構成比は100%積み上げ横棒にする。

## Googleファイルの作り方

作成前に `google-workspace` スキルを読み込む。新規ファイルはGoogleドライブで作り、中身はGoogleスプレッドシート・Googleドキュメントのコネクタで書き込む。集計は数式で作り、元データが更新されると再計算されるようにする。変更は同じファイルに加え、リンクを変えない。
