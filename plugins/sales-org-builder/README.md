# sales-org-builder（営業体制改善構築プラグイン）

営業の属人化を解消し、「担当者が違っても、必要な情報が漏れず、一定品質の提案と引き継ぎができる状態」をつくるためのプラグインです。提案書の作成から、営業診断、標準プロセスの設計、テンプレート整備、KPI・レビュー、ナレッジと育成まで、90日計画の流れに沿って実行できます。

## 収録スキル

| スキル | 90日計画での位置 | できること | 主な成果物 |
|---|---|---|---|
| `sales-standardization-proposal` | 提案 | 営業体制改善の提案書（17枚標準）を作る | Googleスライド／PowerPoint |
| `sales-diagnosis` | 1〜30日 現状把握 | 受注・失注分析、関係者ヒアリング、課題の優先順位づけ | 診断シート、診断レポート |
| `sales-process-design` | 31〜60日 標準化 | 段階と完了条件、案件スコア、受注確率の定義 | プロセス定義書、運用ルール |
| `sales-templates` | 31〜60日 標準化 | ヒアリング・案件サマリー・提案書・見積依頼・引き継ぎのテンプレート | ドキュメント・シート・スライドの雛形一式 |
| `sales-kpi-review` | 31〜90日 標準化〜定着 | 3階層KPI、週次・月次レビュー、ダッシュボード | KPI定義書、レビューシート、ダッシュボード |
| `sales-knowledge-playbook` | 61〜90日 定着・改善 | 事例DB、営業マニュアル、ロールプレイ、育成計画、AI活用 | 事例DB、プレイブック、プロンプト集 |

## 使い方の例

- 「Web制作会社のA社向けに、営業体制の改善提案書をGoogleスライドで作って」
- 「このCRMのエクスポートで受注・失注分析をして、営業課題の優先順位を出して」
- 「営業ステージと次へ進む条件を定義して、案件スコアのシートも作って」
- 「ヒアリングシートと引き継ぎシートを、開発チーム向けに作って」
- 「週次の案件レビューシートとKPIダッシュボードを作って」
- 「成功事例のデータベースと、新人向けのロールプレイ台本を作って」

## 必要な接続

- **Googleドライブ**（必須）: ファイルの作成
- **Googleスライド／Googleスプレッドシート／Googleドキュメント**（推奨）: 作成したファイルの編集と確認。無い場合は新規作成のみになります

このプラグイン自体は外部サービスへの接続設定を含みません。上記のGoogleコネクタを、利用する画面で有効にしてください。

## 品質の考え方

- 事実と仮説を分けて書き、仮説・試算には「仮説」「想定」「目安」と明記します
- 根拠のない数値・実績・事例は作りません
- 前の顧客の固有名詞が残っていないかを、各成果物で確認します
- 修正は同じファイルに加え、リンクを変えません
