# LP・CV導線の改善

## 成果の優先順位
1. **相談予約**（最優先）: 現在は問い合わせフォームで受付しています。予約ツール（日時を選んでその場で予約完了）を導入する計画が `growcross/cvr/booking-tool-plan.md` にあります。予約完了ページ（または完了イベント）をGA4のキーイベント `consultation_booked` にします。
2. **問い合わせ**: フォームの送信完了をキーイベントにします。
3. 資料請求・資料DL（補助）: すぐに相談しない層の受け皿として、業種別のチェックリストなどを検討します（資料の制作が前提）。

### 相談予約ページに載せる要素（チェックリスト）
- 相談で分かること・持ち帰れるもの（例: 営業課題の整理、AI活用の進め方の方向性）
- 対象（中小企業、製造業・サービス業・不動産・介護施設の運営事業者）
- 所要時間・オンライン対応・費用（無料か）・しつこい営業をしない旨（方針に合う場合）
- 担当者の顔写真・経歴、支援実績（掲載許可の範囲内）
- 入力項目は最小限（会社名・氏名・メール・業種・相談したいこと・希望日時）

## 入力
- `profile.md` のCV地点・強み・事例
- サイト診断レポート（CV導線の診断結果）
- GA4のページ別データ（利用できる場合）: セッション、キーイベント（CV）数、CVR

## 手順
### 1. 現状の整理
| ページ | 流入数 | CV数 | CVR | 主な流入元 | 気づいた点 |
|---|---:|---:|---:|---|---|
データがない場合は空欄のままにし、「計測環境の整備」を最優先の改善案にします。

### 2. 改善仮説（観点）
| 観点 | よくある課題 | 改善案の例 |
|---|---|---|
| ファーストビュー | 誰向けの何のサービスか3秒で分からない | 「対象顧客＋解決できる課題＋根拠」を見出しに |
| 訴求の一致 | 広告・投稿の内容とLPの見出しが違う | 流入元ごとに見出しを合わせる（キャンペーンLPを分ける） |
| 信頼材料 | 実績・事例・会社情報が見つからない | 事例・お客様の声・導入の流れ・料金の目安をCTAの近くに |
| CTA | 相談予約への入口が見つけにくい・文言が抽象的 | 全ページのヘッダーと各ページ末尾に「無料相談を予約する」を設置し、業種別ページでは「製造業の営業課題を相談する」など具体的な文言に |
| 業種別の受け皿 | 4業種の見込み客が「自分の会社向けだ」と分からない | 製造業・サービス業・不動産・介護施設の業種別ページ（課題・支援内容・事例・相談予約） |
| フォーム | 項目が多い・必須が多い | 必須項目を絞る（会社名・氏名・メール・相談内容を基本に） |
| スマホ | ボタンが小さい、表が崩れる | 主要CTAを画面下部に固定、表を縦並びに |

### 3. 改善案の優先順位
優先度 = 期待される影響（流入の多いページか）× 実装の手軽さ × 確度。
**数値の改善幅は試算として「想定」と明記** し、確約しません。

### 4. A/Bテスト計画（流入が十分にある場合のみ）
| 項目 | 内容 |
|---|---|
| 仮説 | 〇〇を△△に変えると、□□の理由でCVRが上がる |
| 変更点 | 1回のテストで変えるのは1か所 |
| 指標 | 主指標＝CVR、副指標＝フォーム到達率 |
| 期間・判定 | 各パターンのCVが一定数（目安: 各30件以上）に達するまで。少ない場合はテストせず改善を実施して前後比較 |

### 5. キャンペーンLPの作成（自社MAを使う場合）
```bash
python -m dm_agent call ma_manage_form '{"action":"create","definition":{...}}'          # フォーム定義
python -m dm_agent call ma_create_landing_page '{"slug":"...","title":"...","headline":"...","form_id":"..."}'
python -m dm_agent call build_utm_tracking_url '{"base_url":"https://www.grow-cross.com/lp/...","utm_source":"...","utm_medium":"...","utm_campaign":"..."}'
```
- フォームにはメール配信の同意チェックを設け、プライバシーポリシーへのリンクを置きます。
- グロウクロス用のクライアント設定（`config/clients/growcross.json`）は、`profile.md` の確定後に作成します。

## 出力: `growcross/cvr/YYYY-MM-DD_<ページ>.md`
```markdown
# CV改善案: <ページ名>
## 1. 現状（数値は出典・期間つき）
## 2. 課題と原因（事実／仮説）
## 3. 改善案（優先度｜変更内容｜根拠｜期待効果（想定）｜工数の目安）
## 4. ワイヤー案（ファーストビュー〜CTAまでの構成を箇条書き）
## 5. 計測方法（キーイベント・UTM）
```
