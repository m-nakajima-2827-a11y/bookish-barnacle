# 給与明細PDFの取込仕様

## 1. 処理の流れ
1. ブラウザで pdf.js がPDFのテキスト片（文字列＋座標）を取り出す（`app.js` の `pdfItems`）。サーバーには送信しない。
2. `Payslip.parseItems(items)` がラベル辞書でラベルを探し、**同じ行の右側**か**直下（表形式）**の数値を値として採用する。
3. 読取り結果を画面の表に出し、担当者が確認・修正してから集計シートへ反映する（自動反映はしない）。
4. 文字情報のないスキャンPDFは「文字情報がありません」と表示。OCR済みPDFにするか、手入力・テキスト貼り付けで対応する。

## 2. 抽出する項目とラベル辞書（`payslip.js` の `LABELS`）

| 項目 | ラベル例 | 集計シート |
|---|---|---|
| 総支給金額 | 総支給額、総支給金額、支給合計、支給額合計、賞与支給額 | E列 |
| 社会保険料合計 | 社会保険料合計、社会保険計、社保合計 | F列（合計欄がなければ内訳の合計） |
| 内訳 | 健康保険、介護保険、厚生年金、雇用保険、**子ども・子育て支援金**（2026年4月分から徴収）、厚生年金基金 | 同上 |
| 小規模企業共済等掛金 | 確定拠出年金、マッチング拠出、iDeCo、小規模企業共済 | F列に加算し、L列にも記録 |
| 所得税 | 源泉所得税、所得税（住民税・課税・非課税を含む語は除外） | I列 |
| 扶養人数 | 扶養人数、扶養親族等の数、税扶養 | H列 |
| 支給日 | 「支給日」「支払日」の後の日付。和暦（令和8年4月25日・R8.4.25）・西暦の両対応 | D列 |
| 対象月 | 「令和8年4月分」「2026年4月分」「4月分」、なければ支給日の月 | 行の選択 |
| 賞与判定 | 本文に「賞与」「ボーナス」「期末手当」「勤勉手当」 | 賞与等の行へ |

## 3. 整合チェック（警告として表示）
- 総支給金額・社会保険料・所得税が見つからない
- 社会保険料の内訳合計と合計欄の不一致
- 総支給額 − 控除合計 ≠ 差引支給額（読取り位置のずれの検出）

## 4. 新しい給与ソフトの明細に対応させる
1. 読めなかった項目のラベル文字列を確認する（PDFをテキスト貼り付けで読むと分かりやすい）。
2. `LABELS` の該当キーの配列に追加する（前に書いたものほど優先）。誤検出する語は `EXCLUDE` に追加。
3. `scripts/test_engine.js` の「payslip text」テストにその明細の文字列を追加して確認する。

## 5. CLI（Claude Code から一括処理する場合）
`scripts/parse_payslip.py` は `pdftotext -layout` の結果を同じ辞書で解析し、集計シート用のJSON/CSVを出力します。
```bash
python3 scripts/parse_payslip.py 明細フォルダ/*.pdf --csv 集計.csv
```
出力JSONはアプリの「データ管理 → バックアップを読み込む」形式ではないため、アプリへは画面の取込か、Claudeが employee JSON を組み立てて読み込ませる。
