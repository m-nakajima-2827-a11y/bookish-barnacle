# ② リードスコアリング・クオリフィケーション（score_and_qualify_leads）

## 実行方法
```bash
python -m dm_agent call score_and_qualify_leads '{"lead_ids":["L101","L102"],"analysis_window_days":90}'
python -m dm_agent call score_and_qualify_leads '{}'   # 直近に行動があった全リード
```

## 判定ロジック（重み・しきい値は `config/clients/<client>.json` の icp / scoring。初期値は仮置き）
| 要素 | 内容 |
|---|---|
| フィット（最大50） | 業界（IT・製造業を重視）＋従業員規模＋役職（経営者・営業責任者を重視） |
| エンゲージメント | 資料DL10・セミナー参加15・料金ページ10・事例6など。半減期30日で古い行動ほど低く評価 |
| 企業単位の加点 | 同一企業で2名以上が関与 → +10（購買関与者の広がり） |
| MQL | フィット25以上かつエンゲージメント20以上 → 業界別の育成シナリオへ |
| ホットリード | 問い合わせ／フィット30以上かつエンゲージメント45以上／14日以内に料金ページ閲覧＋資料DL → 営業引き渡し |
| 対象外 | 学生・求職者など → 広告・育成の対象から外す |

グレードは「フィットA〜D × エンゲージメント1〜4」（例: A2）で表示します。

## 守ること
- SQL・商談・受注のステージは営業部門の管轄のため、スコアでは変更されません。
- スコアは設定した重みによる判定であり、購入確率ではありません。「スコア◯点」と報告し、「受注確率◯%」とは書かないでください。
- 月1回を目安に、SQL・受注になったリードのスコア分布を確認し、重みを見直すことを提案してください（営業部門と合意のうえで変更）。
