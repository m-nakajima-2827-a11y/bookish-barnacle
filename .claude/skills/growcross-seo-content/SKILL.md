# SEO記事・ページ制作

## 入力
- `growcross/keyword-map.md` の対象キーワードグループ
- `profile.md`（サービス・強み・事例の掲載可否・表現ルール）

## 手順
### 1. 上位ページの調査（ラッコキーワードMCP）
| 目的 | ツール |
|---|---|
| 上位ページの見出し構成 | `headline` |
| 共起語（内容の網羅性の確認） | `co-occurrence` |
| 読者が持つ疑問 | `question-search` |
| 実際の検索順位 | `search-rank-history`（非同期） |

上位ページに共通する見出し（読者が必ず知りたいこと）と、上位ページにない情報（グロウクロスだから書ける実務の知見・手順・判断基準）を分けて整理します。

### 2. 構成案
```markdown
# 構成案: <主キーワード>
- 想定読者: （役職・状況・悩み）
- 検索意図: （知りたいこと／その後の行動）
- タイトル案（3案、32文字前後、主キーワードを前半に）
- 説明文案（120文字前後）
- 見出し構成（h2/h3）
- 独自性: 上位ページにない、この記事だけの情報
- CTA: 記事のどこで、何（資料DL／相談／問い合わせ）に誘導するか
- 内部リンク: 送り先・送り元のページ
```
構成案の段階で承認者の確認を受けます。

### 3. 本文の下書き
- です・ます調で、結論を先に書きます。
- 事例・数値は、`profile.md` で掲載が許可されたもの、または出典のある公開データだけを使います。出典はURLと取得日を明記します。
- 推測を含む場合は「一般的に」「〜と考えられます」と書き分けます。
- 冒頭の要約、手順や比較は表・箇条書きで示し、AIによる概要や読者が拾いやすい形にします。
- よくある質問（FAQ）の節を設け、`question-search` で見つけた質問に短く答えます。

### 4. 公開前チェック
| 項目 | チェック |
|---|---|
| タイトル・説明文 | 主キーワードを含み、他ページと重複していない |
| 見出し | h1は1つ。h2・h3が構成案どおり |
| 事実確認 | 数値・事例・法律や制度の記述に出典がある／掲載許可がある |
| 表現 | 誇大表現・断定（「必ず」「No.1」など根拠のない表現）がない |
| 内部リンク | 関連するサービスページ・事例・資料DLにリンクしている |
| CTA | 計測用URL（UTM）、または計測できるボタンになっている |
| 構造化データ | Article・FAQPage・BreadcrumbList（必要に応じて） |
| 画像 | alt属性、著作権・肖像権の確認 |

### 5. 公開後
- 公開URLを `keyword-map.md` の「状態」に記録します。
- 4週間後と12週間後に、順位（`search-rank-history`）と流入・CVを `growcross-reporting` で確認します。
- 11〜20位の記事を優先してリライトします。

## 既存ページの改善（リライト）
対象の優先順位: ①問い合わせに近いページ（サービス・料金・事例）②順位が11〜20位の記事 ③表示回数が多いのにクリック率が低いページ（サーチコンソール）

## 出力
- `growcross/content/YYYY-MM-DD_<slug>.md`（構成案・下書き・チェック結果）
- 月次の記事計画: `growcross/content/plan_YYYY-MM.md`（公開予定日｜主キーワード｜検索意図｜担当（想定）｜状態）

## 守ること
- サイトへの公開・既存ページの書き換えは、承認後に担当者が行うか、承認を得てから実行します。
- 他社の記事の文章をそのまま、または言い換えただけで使いません。
