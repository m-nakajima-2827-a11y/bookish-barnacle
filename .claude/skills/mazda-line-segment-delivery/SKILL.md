# マツダ LINE OnetoOne セグメント配信（mazda_line_segment_delivery）

マツダ販売店のLINEシステムから出力した「お友だち登録データ」をもとに、次の順で作業します。

1. データの読み込みと前処理
2. お友だちの分析（車種・車検時期・経過年数・加入状況・店舗・担当者）
3. 分岐（優先度・補助分岐）への振り分け
4. 分析結果のExcel作成（決まった書式・説明・改善点つき）
5. 分岐別のLINEメッセージ案（各3案）と配信スケジュール
6. 年収別の適正車種と、年収帯別のメッセージ（年収データがある場合）
7. ステップ配信・季節配信の案

| ファイル | 内容 |
|---|---|
| `SKILL.md`（このファイル） | 手順、分岐ルール、Excelの仕様、出力物、チェックリスト |
| `references/branch-messages.md` | 分岐別メッセージ案（至急・A1・A2・A3・B・C1・C2・X1・X2・X3 × 各3案） |
| `references/income-step-season.md` | 年収別の適正車種一覧、年収帯別メッセージ（6区分×3案）、ステップ配信（1〜4回目）、季節配信とバナー案 |
| `scripts/` | 実行用スクリプト（任意。4-5を参照） |

**表記のルール**：集計値は【事実】、データからの推定や施策の見込みは【仮説】、一般的な目安・試算は【目安】と書き分けます。根拠のない数値は作りません。

## 1. データの読み込みと前処理

### 1-1 入力ファイル（LINEシステムの「お友だち登録データ」CSV）
- ファイル名の例：`regist_YYYYMMDDhhmmss.csv`（ファイル名の日時＝出力日。これを**基準日**にする）
- 文字コード：**Shift_JIS（CP932）**。UTF-8に変換してから読み込む
- 値の形式：電話番号・はい／いいえなどは `="09012345678"` `="はい"` の形で入っている。先頭の `="` と末尾の `"` を取り除く
- **1行＝お友だち×車両1台**。複数台お持ちの方は複数行になる

| 列 | 使い方 |
|---|---|
| No | 登録番号（配信リストのキー） |
| 種別・担当職 | 参考（担当職はほぼ空欄） |
| お名前(姓)・お名前(セイ・名)・LINEユーザ名 | 差し込み `{お名前}`、確認用 |
| 誕生月 | 誕生月メッセージ（年齢の列はない） |
| 電話番号 | 名寄せ（同じ人の複数台を判定）。**配信リスト・報告書には出さない** |
| 担当店舗(管理者店舗)・担当者・入庫店舗 | 店舗・担当者別の集計、差し込み `{店舗名}` `{担当者名}` |
| 車種 | 車種・車格・提案車種の判定 |
| 登録ナンバー（陸事・種別・かな・連番） | 分析には使わない |
| 任意保険の加入・パックdeメンテの加入・スカイプランの加入 | 加入状況の分析、補助分岐、A1の判定 |
| 登録日 | 車の登録日（経過年数の計算） |
| 車検日 | 車検満了日（車検時期・ステップ配信日の計算） |
| お友だち登録日 | 登録年別の集計（ブロック率の確認） |

### 1-2 前処理のルール
| 処理 | 内容 |
|---|---|
| 表記ゆれの統一 | 担当者「サ-ビス」→「サービス」、担当者が空欄 →「(未設定)」 |
| 経過年数（現在） | （基準日 − 登録日）÷365.25 |
| 次回車検時の経過年数 | （車検日 − 登録日）÷365.25 を四捨五入 → 3年以内＝初回、4〜5年＝2回目、6〜7年＝3回目、8〜9年＝4回目、10年以上＝10年超 |
| 車検まで(月) | （車検日 − 基準日）÷30.44 |
| 車検時期 | 2か月以内／2〜3か月／4〜6か月／7〜12か月／13か月以上 |
| 名寄せ | 電話番号が同じ行を同一人物とし、「複数台保有」に印を付ける |
| データ品質の記録 | 入庫店舗「0」、担当者未設定、車種「その他(…)」の表記ゆれ、加入状況の空欄を件数で記録する |

## 2. お友だちの分析

次の切り口で集計し、それぞれExcelのシートにします（シートの仕様は「4. Excelの仕様」）。

| 切り口 | 見るポイント |
|---|---|
| 概要 | 件数、名寄せ後の人数、複数台保有、店舗別件数、加入率、平均経過年数、車検6・12か月以内の件数 |
| 車種別 | 件数・構成比・平均経過年数・車検6か月以内・スカイプラン加入・パックdeメンテ加入率。販売終了の車種に印 |
| 車格別 | 車格ごとの量と、販売終了・旧名称の件数 |
| 店舗×車検時期 | 至急の件数、店舗ごとの入庫負荷 |
| 次回車検の回数×店舗 | 年齢の代わり。7年以上・10年超が乗り換えの優先層 |
| 車検カレンダー12か月 | 満了月の山（決算期の3月など）と、試乗枠・入庫枠の準備 |
| 優先度×店舗 | 分岐ごとの件数 |
| 担当者別 | 担当者ごとの件数・優先度別件数・フォローの偏り |
| 加入状況×車検時期 | 車検が近い未加入者（入庫時の案内対象） |
| 暫定価格帯セグメント | 年収別メッセージの暫定の対象 |
| 誕生月 | 誕生月メッセージの対象数 |
| お友だち登録年 | 古い登録の層（ブロック率に注意） |
| データ品質 | 修正・追加取得が必要な項目 |

分析コメントは「事実（集計値）→ 仮説（読み取り）→ 施策」の順に書きます。
例：「ミニバン147件は平均12.6年と最も古い（事実）。マツダにはミニバンの後継車がないため、他メーカーに流れやすい層と考えられる（仮説）。CX-80・CX-5の試乗案内を優先する（施策）。」

## 3. 分岐ルール

### 3-1 主分岐（上から順に判定し、1件は1つの分岐にだけ入る）
| 分岐 | 条件 | 目的 |
|---|---|---|
| **至急** | 車検まで2か月以内（ステップ配信の4回目の日付を過ぎている） | 車検予約の確定。乗り換えの相談は担当者の電話へ |
| **A1** スカイプラン満了期 | スカイプラン加入 かつ 車検6か月以内 | 満了時の選び方の説明と乗り換えの商談 |
| **A2** 販売終了車種 | 車種区分が販売終了 かつ 車検6か月以内 | 後継・近いサイズの車種の案内（他メーカーへの流出防止） |
| **A3** 7年以上 | 次回車検時の経過年数7年以上 かつ 車検6か月以内 | 「車検を通す」と「乗り換える」の比較 |
| **B** 車検予約 | A1〜A3以外で車検6か月以内 | 自店での車検の予約 |
| **C1** 準備層 | 車検まで7〜12か月 | 意向・予算のアンケート、ステップ配信への準備 |
| **C2** 関係維持 | 車検まで13か月以上 | 季節情報を少ない頻度で配信、予算データの収集 |

※至急は、A1〜Bの方のうち車検2か月以内の方を先に抜き出したものです。至急の方にはA1〜Bの案を送らず、至急の案と担当者の電話で対応します。
※スカイプランの加入フラグは「現在の契約」を表します（販売店に確認済み）。A1は「現在スカイプランで契約中 かつ 車検6か月以内」の方です。満了の時期は契約ごとに違うため、案の配信前に契約内容で確認します（登録日は車の初度登録日のため、中古車でご契約の方は登録日から満了時期を推定できません）。

### 3-2 補助分岐（主分岐と重ねて使う）
| 分岐 | 条件 | 目的 |
|---|---|---|
| **X1** パックdeメンテ未加入 | 加入「いいえ」かつ 車検6か月以内 | 車検の入庫に合わせて加入を案内 |
| **X2** 任意保険未加入 | 加入「いいえ」かつ 車検6か月以内 | 保険の満期の確認と見直しの相談 |
| **X3** 誕生月 | 誕生月が配信月 | お祝いと来店のきっかけづくり |

### 3-3 ステップ配信日
車検日の **6か月前（1回目）・4か月前（2回目）・3か月前（3回目）・2か月前（4回目）**。基準日より前の回は「経過」とし、「次に送るステップ」を配信リストに記録します。

### 3-4 配信のルール
| ルール | 内容 |
|---|---|
| 優先順位 | 至急 → A1 → A2 → A3 → B → X1・X2 → C1 → C2。同じ週に複数の分岐に入る方には、優先順位の高い1通だけ送る |
| 頻度の上限 | 1人あたり月4通まで。C2は月1〜2通まで |
| 配信しない時間 | 22時〜翌8時 |
| 複数台保有 | 電話番号で重複を除き、優先順位の高い車両の分岐で1通だけ送る |
| 3案の使い方 | 案1→案2→案3の順に送る。反応（リンククリック・予約・返信）があった方には次の案を送らず、担当者が個別に連絡する |
| 計測 | URLにUTMを付ける（例：`utm_source=line&utm_medium=onetoone&utm_campaign=a1_01`）。`build-utm-tracking-url` を使ってよい |

## 4. Excelの仕様（分析結果の一覧表）

### 4-1 ファイルとシート
ファイル名：`LINE_お友だち分析_YYYYMMDD.xlsx`（YYYYMMDDは基準日）

| シート | 内容 | 関数 |
|---|---|---|
| 01_概要 | 項目・値・説明 | 件数・加入率・車検件数は配信リストからCOUNTIF。名寄せ人数・複数台・平均経過年数は値 |
| 02_車種別 | 車種ごとの集計＋車格・車種区分・提案車種。販売終了の「車種区分」セルを黄色 | 構成比＝件数÷合計、合計＝SUM |
| 03_車格別 | 車格ごとの集計 | 構成比、合計＝SUM |
| 04_店舗×車検時期 | 店舗×5区分 | 行・列の合計＝SUM |
| 05_次回車検の回数×店舗 | 回数×店舗 | 合計＝SUM |
| 06_車検カレンダー12か月 | 満了月×店舗 | 合計＝SUM |
| 07_優先度×店舗 | 主分岐（A1〜C2）×店舗。至急はA1〜Bの再掲のため行に含めない（配信計画書に「（再掲）至急」として記載） | 合計＝SUM |
| 08_担当者別 | 店舗・担当者・件数・車検6か月以内・優先度A計・A1・A2・A3・B・C1・C2・件数との一致確認 | 配信リストからCOUNTIFS、優先度A計＝SUM、一致確認＝IF（A1〜C2の合計＝件数なら「OK」）、合計行＝SUM |
| 09_加入状況×車検時期 | 3つの加入状況（はい・いいえ・空欄）×車検時期 | 合計＝SUM |
| 10_暫定価格帯セグメント | 価格帯・**対象車種（保有車と件数）**・車検時期5区分・合計 | 合計＝SUM |
| 11_誕生月 | 誕生月×店舗。合計列の見出しは「対象者合計」 | 合計＝SUM（誕生月が空欄の行は含まれない） |
| 12_友だち登録年 | お友だち登録年×店舗。合計列の見出しは「登録数合計」 | 合計＝SUM |
| 13_データ品質 | 項目・件数／状況・対応。入庫店舗「0」、担当者未設定、「サービス」担当、担当職の空欄、車種「その他(…)」、加入状況の空欄、誕生月の空欄、生年・年収・最終来店日の有無 | ― |
| 20_配信リスト | 1件ごとの一覧（下記の列）。見出しにフィルター | ― |

**20_配信リストの列**：No、お名前(姓)、LINEユーザ名、店舗、担当者、車種、車格、車種区分、提案車種、登録日、車検日、車検まで(月)、次回車検の回数、任意保険の加入、パックdeメンテの加入、スカイプランの加入、優先度、暫定価格帯セグメント(仮説)、次に送るステップ、1回目〜4回目配信日、複数台保有。**電話番号は載せない。**

| 罫線 | 表のすべてのセルに細線。11・12シートの合計列は二重線 |
| 強調 | 02シートの販売終了＝黄色（#FFFF00） |
| 数値 | 構成比 0.00%、加入率 0.0%、パックdeメンテ加入率 0%（文字ではなく数値で入れる） |

### 4-4 作成後の確認
- 関数のエラー（#NAME?、#REF!など）がないこと
- 08シートの「件数との一致確認」がすべて「OK」で、優先度別の合計が07シートと一致すること
- 合計値が元データの件数と一致すること
- LibreOfficeなどで再計算して確認する。ファイルは「開いたときに再計算」を有効にして保存する

## 5. 分岐別のLINEメッセージ案（各3案）

`references/branch-messages.md` のひな形を使い、分析結果に合わせて次のものを作ります。

1. **分岐の全体像**：分岐ツリーと各分岐の件数（店舗別）【事実】
2. **配信スケジュール表**：分岐 × 案1〜3 の配信日時（基準日から具体的な日付に置き換える。同じ週に重ならないようにずらす）
3. **各分岐のメッセージ3案**：目的、特徴（多い車種・経過年数など【事実】）、案1〜3の本文、次の分岐（反応あり／なし）
4. **KPI**：分岐ごとの指標（車検予約率、試乗・査定予約数、アンケート回答率、ブロック率、加入件数）

| 分岐 | 案1 | 案2 | 案3 |
|---|---|---|---|
| 至急 | 車検時期のお知らせ | 代車・所要時間のご案内 | 担当者からの最終のご連絡（＋電話） |
| A1 | 満了時の選び方 | 乗り換えた場合のお見積り | 満了相談会 |
| A2 | 近い現行車種の紹介 | 乗り比べ試乗 | 乗り続ける場合との比較 |
| A3 | 比較資料のご案内 | 後継・近い車種の紹介 | 無料査定 |
| B | 早期予約 | 点検の安心感 | 予約のリマインド |
| C1 | 意向・予算アンケート | 季節点検と査定 | ステップ配信1回目へ移行 |
| C2 | 季節のメンテナンス | 予算アンケート | 年末などの点検 |
| X1 | 予約のお礼と案内 | 入庫前の確認 | 車検後のお礼と点検スケジュール |
| X2 | 保険の満期の確認 | 入庫時の相談 | 事故・故障時の窓口 |
| X3 | お祝い／担当者から／来店のきっかけ（3案から1案を選ぶ） | | |

**文面のルール**
- 1通150〜250字。差し込み `{お名前}` `{店舗名}` `{担当者名}` `{保有車種}` `{提案車種}` `{車検満了月}` `{URL}` を使う
- 年収・家族構成などの個人情報を本文に書かない
- 価格・月々のお支払い額を載せる場合は、支払回数・実質年率・頭金・残価・総支払額などの条件を併記する（最終確認は本部・信販会社）
- 保険の案内は、保険会社・代理店の規程を確認してから送る
- 「最安」「絶対」「必ず」など、根拠を示せない表現は使わない

## 6. 年収別の適正車種と年収帯別メッセージ

`references/income-step-season.md` の②③を使います。
- 年収データがある場合：年収帯（300万〜400万円／401万〜500万円／501万〜600万円／601万〜700万円／701万〜800万円／801万円以上）ごとに各3案
- 年収データがない場合：1-4の暫定価格帯セグメントで代用し、「暫定（仮説）」と明記する
- 車両価格は年収の40〜50%、残価設定型ローンを使う場合の上限は年収の60%を【目安】とする。価格表・金利は最新のものに置き換える

## 7. ステップ配信・季節配信

`references/income-step-season.md` の④⑤を使います。
- ステップ配信：車検の6・4・3・2か月前の4通。至急・Bの分岐と内容が重なるため、同じ週には送らない
- 季節配信：年間カレンダーにもとづくメンテナンス2案とオススメ車種2案（バナー案つき）。小田原・秦野のように降雪の少ない地域では、使う場面（山道・スキー）を添える

### 4-5 実行用スクリプト（任意）
4章の仕様どおりのExcelと、5章の文書を自動で作るスクリプトを `scripts/` に同梱しています。手作業で作る場合も、仕様の確認に使えます。

```bash
# 1) 文字コードをUTF-8に変換（作業用フォルダで行う）
iconv -f CP932 -t UTF-8 regist_YYYYMMDDhhmmss.csv > friends.csv
# 2) 分析・分岐・Excel（改善点は集計値から自動で作文）＋ 数値のJSON
python3 scripts/run_skill.py friends.csv regist_YYYYMMDDhhmmss.csv LINE_お友だち分析_YYYYMMDD.xlsx result.json
# 3) 分岐別メッセージ案と配信計画書（references/branch-messages.md の相対日付を具体的な日付に置き換える）
python3 scripts/gen_docs.py result.json references/branch-messages.md <出力フォルダ>
```

| ファイル | 内容 |
|---|---|
| `scripts/run_skill.py` | 1〜4章（前処理・車種分類・暫定価格帯・分岐・ステップ配信日・14シートのExcel・改善点） |
| `scripts/texts.py` | 各シートのタイトル・分析内容・見方・項目の説明 |
| `scripts/gen_docs.py` | 5章（分岐ツリー・配信スケジュール・各分岐3案・KPI）と配信計画書 |

- 必要なもの：Python 3、pandas、openpyxl。関数の確認には LibreOffice（`soffice --headless --convert-to xlsx`）で再計算する。
- 分類表にない車種が出た場合は、実行結果の `unclassified` に表示される。1-3の表とスクリプトの `CLS` に追加する。
- 出力ファイルにはお名前が含まれるため、リポジトリの外（作業用フォルダ）に出力する。

## 9. 配信前チェックリスト
- [ ] ブロック済み・配信非同意の方を除外した
- [ ] 複数台保有の方の重複を除いた
- [ ] 至急の方に、A1〜Bの案を同じ週に送っていない
- [ ] 本文に年収・家族構成などの個人情報を書いていない
- [ ] 価格・お支払い例・保険の表現を、最新の条件と規程で確認した

## 10. 使い方の注意
- メッセージ・配信時期・価格帯は**ひな形と目安**です。初回の配信結果（クリック率・予約率・ブロック率）を基準値にして見直します。
- 車種のラインアップ・価格・キャンペーンは変わるため、配信のたびに最新の公式情報を確認します。
- マツダのロゴ・写真素材・車名の表記は、メーカー・本部の使用ルールに従います。
